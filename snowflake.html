Manufacturing Data Pipeline

Azure Blob Storage to Snowflake Bronze / Silver / Gold

Manufacturing environments spread their data across systems that were never designed to talk to each other. Supplier records, production logs, and equipment telemetry all arrive in different shapes, and every one of them needs work before anything can be joined. I built a pipeline to pull all of it into a single queryable layer.

Architecture: Raw CSV files land in Azure Blob Storage and flow into a Bronze, Silver, and Gold medallion setup in Snowflake. Bronze keeps the source data exactly as it arrived, so there is always something to go back to. Silver is where the work happens: UNPIVOT to reshape the metrics, LATERAL FLATTEN to open up the JSON device telemetry, and surrogate keys to make the dimensional model hold together. Gold is what analysis touches, delivering a supplier scorecard and a quality trend layer.

Key Output: A Snowflake warehouse that answers the questions an operations team keeps coming back to. How each supplier is performing on delivery, where the defects are concentrated, and which vendors are contributing the most downtime in any given period.

Minimum Wage Compliance Model

Azure Blob Storage to Snowflake to Power BI · Professional Build

The benefits in establishing data pipelines for real-time updates have been a must in my experience. More often than not, that is what made proactive workforce management and continuous compliance monitoring possible in the first place.

Minimum wage law changes at the state and local level meant we were carrying exposure across a lot of jurisdictions at once, and it moved constantly. I built a compliance model that checked every active employee against the minimum that applied to them, right down to the city-level overrides in California. Raw payroll data landed from Azure Blob Storage into Bronze, went through transformation in Silver, and materialized in Gold for Power BI to report on.

Architecture: Bronze held the raw CSV exactly as it came in, data quality problems and all, because that is the point of a landing zone. Silver did the cleanup: TRY_TO_DOUBLE to strip out dollar signs and commas, CASE statements to normalize the job class variants, and a UNPIVOT through UNION ALL that turned three rate period columns per jurisdiction into one row per period. Remote employees got resolved to their work state through COALESCE. A 5% buffer flagged At Risk employees while there was still time to correct it.

Gold layer: Two materialized mart tables did the heavy lifting. MART_COMPLIANCE_CURRENT gave one row per active employee with their compliance status and annualized exposure. MART_COMPLIANCE_UPCOMING looked ahead, one row per employee for every upcoming rate period. Power BI connected to Gold and nothing else, which kept the reporting layer clean.

Key Output: A monthly compliance dashboard that surfaced exposure by jurisdiction, title, and employee, with enough lead time for people to act before the effective dates hit.

Snowpipe with AWS S3

Automated Pipeline Ingestion from AWS S3 to Snowflake

I built a pipeline connecting AWS S3 to Snowflake that watches for file uploads and processes whatever lands, structured or unstructured, so the warehouse updates itself as new data arrives.

Goal: Getting the warehouse to update on its own whenever new data shows up.

AWS S3 buckets handled the storage and IAM handled the secure connection between the two. On the Snowflake side I built the objects that receive and stage whatever comes through.

Those objects are the databases, schemas, and tables that sit at the end of the pipe.

Once it was running, any new upload streamed straight through and became a live feed of new records. I used a similar setup to keep continuous watch on workforce wages and data integrity inside our HCM, which is where this pattern really proved itself.
