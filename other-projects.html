Data Cleaning in SQL

Nashville Housing · Reliable Analysis Starts with Clean Data

Cleaning and transformations are the unsung heroes in driving any analysis forward. Nobody puts them in a presentation, but every number downstream depends on them.

Goal: Getting the Nashville Housing dataset into a state where analysis is actually possible.

  • The first query tells you what you are dealing with. Missing values scattered throughout and records that do not line up the way you would want them to.
  • I cleaned and standardized the records to close the gaps and get the formatting consistent across the table.
  • Splitting the address into its own columns made the data readable and gave me something to filter on later.
  • A View handled the duplicate removal, which kept the raw data intact. Deleting from source is the kind of shortcut you regret two months later.
Key Insights:
  • Properties can have multiple owners, which matters a great deal if you are analyzing anything at the individual level.

Snowpipe with AWS S3 and Azure Blob Storage

Automated Pipeline Ingestion into Snowflake

I built a pipeline connecting cloud object storage to Snowflake that watches for file uploads and processes whatever lands, structured or unstructured, so the warehouse updates itself as new data arrives.

Goal: Getting the warehouse to update on its own whenever new data shows up.

AWS S3 buckets handled the storage and IAM handled the secure connection between the two. On the Snowflake side I built the objects that receive and stage whatever comes through. The same pattern works against Azure Blob Storage using a storage integration and a notification queue in place of the S3 event.

Those objects are the databases, schemas, and tables that sit at the end of the pipe.

Once it was running, any new upload streamed straight through and became a live feed of new records. Being able to pause the pipe matters more than it sounds, because it lets you hold ingestion while a source problem gets fixed rather than loading bad data and cleaning up after.

I used a similar setup to keep continuous watch on workforce wages and data integrity inside our HCM, which is where this pattern really proved itself.
